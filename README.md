# Smart Logistics Data & ML Platform — Технический отчет и документация

Проект представляет собой сквозной прототип аналитической и ML-платформы для рынка грузоперевозок (B2B SaaS Умная Логистика). Решение реализует полный цикл работы с данными: от пакетного ETL-пайплайна с контролем качества и идемпотентностью до построения аналитических витрин и пакетного ML-скоринга на базе CatBoost.

## 2. Этап 1: ETL и контроль качества (Data Quality)

Пайплайн (`etl/pipeline.py`) отвечает за извлечение сырых данных, проверку качества, конвертацию валют по курсам ЦБ и безопасную идемпотентную загрузку в слой **Core DWH** (`core.cleaned_prices`).

### Особенности реализации:

1. **Валидация и карантин:** Невалидные записи (нулевые/отрицательные цены, некорректная дистанция, битые веса и объем, а также отсутствие городов в справочнике) отсеиваются и направляются в карантинную таблицу `dq_quarantine_prices` с фиксацией причины (`dq_reason`).
2. **Конвертация валют:** Поддерживаются рубли (`643`), доллары (`840`) и евро (`978`). Курс подтягивается по точному совпадению с `nearest_rate_date`. Если курс не найден, строка перенаправляется в карантин.
3. **Идемпотентность:** Перед вставкой свежего пакета данных за выбранный период выполняется идемпотентный `DELETE` по диапазону дат погрузки (`loading_date`), исключая задвоение при повторных запусках:
```python
conn.execute(text(f"DELETE FROM core.cleaned_prices WHERE loading_date >= '{start_date}' AND loading_date <= '{end_date}';"))

```

## 3. Этап 2: Аналитический слой (Mart Layer)

Для обеспечения BI-систем (например, Apache Superset) быстрыми агрегатами спроектирована витрина **`mart.mart_market_corridor`**. Она устраняет структурные аномалии исходных справочников (дедупликация городов по `gc_id`, унификация групп кузовов по `std_id`) и рассчитывает рыночные коридоры ставок.

### Ключевые метрики витрины:

* **Рыночный коридор за рейс и за 1 км:** 25-й (`p25`), медиана (`median_trip` / `median_km`) и 75-й (`p75`) перцентили с использованием функции `PERCENTILE_CONT`.
* **Доказательная база:** `trips_count` (число сделок), `carriers_count` (уникальные перевозчики), коэффициент вариации `cv_rate`.
* **Динамика:** `mom_pct` (к предыдущему месяцу) и `yoy_pct` (к прошлому году).
* **Уровень надежности (`reliability_level`):** Автоматическая классификация направлений на `HIGH`, `MEDIUM` и `LOW_DATA` в зависимости от плотности сделок.

## 4. Этап 3: ML Feature Engineering & Batch Inference

Модуль (`ml/train_predict.py`) решает задачу прогнозирования справедливой ставки перевозчика за километр (`price_per_km`) с последующим пересчетом в стоимость рейса и построением доверительного интервала (коридора P25–P75).

### Архитектура ML-пайплайна:

1. **Защита от Leakage:** Из признакового пространства полностью исключены прямые производные таргета (ставка с НДС, удельные показатели текущего рейса, маржа) и агрегаты текущего месяца (`price_group_stats`), предотвращая заглядывание в будущее.
2. **Хронологический сплит (Time-Based Split):**
* **Train:** Июль – Август 2026 (`< 2026-09-01`)
* **Validation:** Сентябрь 2026 (`09-01` по `10-01`)
* **Test:** Октябрь 2026 (`>= 2026-10-01`)


3. **Модель:** `CatBoostRegressor` с категориальными признаками (`loading_city_gcid`, `unloading_city_gcid`, `body_type`, `weight_category`, `volume_category`) и циклическими временными фичами (`month`, `day_of_week`).

## 5. Инструкция по быстрому запуску

Проект полностью контейнеризирован и развертывается одной командой.

1. **Создайте файл окружения** на основе шаблона:
```bash
cp .env.example .env

```


2. **Запустите инфраструктуру** (PostgreSQL 17):
```bash
docker compose up -d

```


3. **Установите зависимости Python:**
```bash
pip install -r requirements.txt

```


4. **Запустите ETL-пайплайн** для наполнения Core-слоя:
```bash
python etl/pipeline.py

```


5. **Запустите ML-пайплайн** для обучения модели и генерации пакетных прогнозов:
```bash
python ml/train_predict.py

```
